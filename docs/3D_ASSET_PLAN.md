# 강아지 3D 자산 제작 계획

## 목표

실제 강아지의 얼굴과 체형을 최대한 사실적으로 닮게 만든 모델을 Blender에서 제작하고, 추후 Unity에서 움직일 수 있는 형태로 전달한다. 사용자가 제시한 사실적인 털 모델을 품질 참고로 삼는다. 작은 화면에서도 특징이 잘 보이도록 필요한 부분만 표현을 조정한다. 3D 원본의 디테일과 실시간 앱에 들어갈 모델을 분리해 관리한다. 현재 원격 작업 환경에는 Blender 4.3.2가 있다. 사용자는 Windows에서 Blender 5.2.2 LTS를 실행했다고 알려 주었으며, 그 환경의 실제 버전과 파일 호환성은 여기서 검증하지 않았다. ZIP으로 받은 사진 원본 17장은 `ReferencePhotos/`에 보관하며 Git 추적에서 제외한다.

원격 환경에서 만든 `.blend`는 사용자의 Blender에서 실제로 열어 호환성을 확인한다. 더 높은 버전에서 저장한 파일을 구버전 4.3.2로 다시 여는 흐름은 피하고, 수정본을 되돌릴 때는 호환되는 내보내기 파일 또는 작업 환경의 버전을 맞춘다. 현재 가능한 작업은 이 환경에서의 Blender 파일 처리·스크립트 수정·렌더링이다. 사용자의 Windows Blender 화면을 직접 조작하는 연결은 없다.

털 시험부터는 이 작업 환경에 공식 Blender Python 모듈 `bpy==5.2.2`도 별도로 설치했다. v03 털 장면은 Blender 5.2.2 LTS에서 저장·재열기·렌더를 확인했다. 기존 CLI Blender 4.3.2와 구분해 사용하며, 사용자의 Windows 환경에서 직접 확인한 것은 아니다.

현재 사진에서 확인한 외형 특징과 추가로 필요한 각도는 [사진 분석 기록](REFERENCE_ANALYSIS.md)에 정리했다.

## 현재 판단과 다음 입력

`ArtSource/ogong_blockout_v01.blend`와 `ArtSource/ogong_blockout_v02.blend`는 사용자가 외형 품질을 거절한 실험이다. 구형 도형을 합치고 무작위 털을 더하는 접근으로는 요구한 얼굴 구조와 부드러운 털을 재현하지 못했다. 기존 파일과 `Previews/`의 렌더는 기록으로 보관하며, 이 모델을 제작 기반으로 계속 다듬지 않는다.

다운로드 결제가 필요한 사용자의 기존 Meshy 결과는 현재 제작 경로에서 제외한다. 이후 첨부한 `golden-retriever-dog-3d-model-free.zip`은 32 MiB 전송 한도에 걸렸으나, 따로 올린 약 29.66 MiB의 GLB는 정상 수신했다. Blender에서 구조 검사와 정면·측면·45도·무채색 렌더를 마쳤다. 몸체와 털 표현의 참고로 채택하며, 오공이의 얼굴·귀·꼬리 및 애니메이션용 표면은 새로 구성해야 한다. 실제 측정값과 판단은 [리트리버 자산 검토](RETRIEVER_ASSET_REVIEW.md)에 기록했다. 기존 사진 17장은 다시 받을 필요가 없다.

[Sketchfab 참고 링크](https://sketchfab.com/3d-models/dog-pomeranianavailable-for-3d-printing-e37bac6fcd3e407ea1e01a688ce68071)는 제목상 프린팅용 자산이다. 이 용도의 메시도 형상 참고로 활용할 수 있지만, 움직이는 강아지의 기반으로 쓰려면 관절 주변 표면과 분리된 다리 등을 원본에서 확인해야 한다. 프린팅용이라는 이유만으로 리그가 없거나 수정할 수 없다고 단정하지 않는다.

상품 사양은 [판매 페이지](https://www.turbosquid.com/3d-models/3d-pomeranian-dwarf-spitz-dog-cream-sable-fur-for-cinema-4d-model-2491697)를 2026-10-05에 확인했다. 판매 렌더의 털 품질을 몸체의 폴리곤 수만으로 판단하지 않는다. 설명상 털 생성 기능이 따로 있으므로 일반 메시 내보내기로 동일한 외형이 보존된다고 가정할 수 없다. [TurboSquid 변환 안내](https://www.turbosquid.com/help/en/articles/9937269-file-format-conversion-requests) 역시 변환 가능 여부가 제품과 형식에 따라 달라진다고 명시한다. 구매 후보로 선택하기 전 Blender에서 사용할 몸체·털 파일 구성과 리그 포함 여부를 확인한다.

해당 상품은 Standard License로 표시된다. [사용 조건](https://www.turbosquid.com/licensing)은 수정 및 앱에 포함하는 사용을 허용하면서 모델 원본의 재배포를 제한한다. 채택할 경우 구매 자산과 파생 원본은 공개 저장소에 올리지 않고 앱 배포 조건을 따른다. 현재 구매나 다운로드는 하지 않았다.

### 모델 검사와 후속 제작

리트리버 GLB의 내장 텍스처까지 확인했고, 원본 복사본과 검사 장면은 `ReferenceAssets/retriever/`에 보관했다. 원본의 형상·재질을 변경하지 않고 카메라와 조명을 추가해 비교했다. 아래 검사 절차는 향후 후보에도 적용한다.

1. 원본을 보존하고 복사본에서 단위·축·오브젝트·삼각형 수를 기록한다.
2. 다리와 몸이 붙은 부분, 구멍, 뒤집힌 면, 입·눈 구조, UV·재질·리그를 검사한다.
3. 정면·측면·45도에서 오공이 사진과 비교한다. 회색 참고 스크린샷의 주둥이는 오공이보다 길어 보인다. 새 기반의 측면에서도 이 차이를 확인한다.
4. 원형 수정으로 쓸 수 있는지, 조각 참고로만 쓸지 결정한다. 앉은 자세에서 다리가 몸에 붙어 있다면 서 있는 중립 자세와 관절 주변 표면을 새로 구성해야 한다.
5. 리트리버의 경우 주둥이·귀·머리 크기·다리 비율·말린 꼬리·털 분포를 크게 바꿔야 한다. 몸체나 관절 구조만 활용할지 원본 검사 후 판단한다. 수정이 비효율적이면 무료로 접근할 수 있는 서 있는 포메라니안 기반 메시를 다음 후보로 검토한다.

## 1. 참고 자료 모으기

가능하면 같은 날, 밝고 부드러운 조명에서 강아지의 눈높이로 촬영한다. 휴대폰 광각 렌즈를 얼굴 가까이에 대면 비율이 왜곡되므로 조금 떨어져서 촬영한다. 필터와 과한 배경 흐림은 피한다.

| 자료 | 용도 |
| --- | --- |
| 얼굴 정면, 45도, 양쪽 측면 | 눈·코·입·귀의 위치와 얼굴형 |
| 서 있는 전신 정면, 양쪽 측면, 뒤쪽 | 몸통·다리 비율과 털 실루엣 |
| 위에서 본 사진과 꼬리 근접 사진 | 등선, 꼬리 형태와 털 방향 |
| 걷기·앉기·눕기 짧은 영상 | 실제 자세와 보행 리듬 |
| 가능하면 어깨 높이·몸길이 측정값 | 모델의 비율과 크기 기준 |

사진 17장으로 얼굴과 체형 검토를 시작한다. 추가 촬영은 특정 부분을 판단할 수 없을 때 필요한 각도만 요청한다. 원본 사진은 기본적으로 Git 저장소에 올리지 않는다.

## 2. 외형 분석과 기본 형태

사진을 정면·측면 기준 이미지로 정리하고 얼굴 폭과 길이, 눈 간격, 귀 각도, 주둥이 길이, 몸통·다리 비율을 기록한다. 검사를 통과한 기반 메시에서 눈구멍·눈꺼풀, 짧은 주둥이와 입술, 털에 묻힌 작은 삼각형 귀를 수정한다. 몸통과 별개로 가슴 털의 부피, 짧게 드러나는 다리, 작은 발, 등 위로 말린 꼬리를 맞춘다. 털 아래의 체형과 털이 만드는 외곽선을 구분해서 비교한다.

정면·측면·45도에서 무채색 표면과 털 부피 가이드를 확인한다. 이 단계에서 얼굴과 실루엣이 닮았는지 검토하고 차이가 큰 부분을 먼저 수정한다. 털 아래의 구조는 사진에 보이지 않는 부분이 있으므로 추정한 부분을 기록한다.

세부 털이나 재질보다 **실루엣과 얼굴 비율**을 먼저 맞춘다. 특히 화면에서 작은 크기로 표시될 때 알아볼 수 있는 특징을 유지한다.

## 3. 세부 모델·털·재질

최초의 **얼굴·가슴 흰 털 시험**은 리트리버의 얼굴 비율을 유지했다. 이후 사용자가 얼굴 자체도 포메라니안처럼 고치도록 요청해, 새로운 둥근 머리 표면과 작은 삼각형 귀·어두운 눈을 만들고 주둥이·입·혀의 비율을 수정했다. 털도 새 표면에 다시 구성했다. 최신 편집용 장면과 남은 작업은 [얼굴 수정 기록](FACE_REBUILD.md), 이전 시험은 [털 시험 기록](FUR_STUDY.md)을 따른다. 보호자가 닮은 정도를 확인하기 전 외형이 완성됐다고 판정하지 않는다.

눈·코·귀·발·꼬리를 다듬고 털의 부피와 방향을 만든다. 이마·볼·목·가슴·몸통·꼬리별로 털의 뿌리와 흐름을 설계하고, 길이·밀도·뭉침을 조정한다. 무작위 직선 털을 전체 표면에 뿌리는 방법은 반복하지 않는다. Blender 원본에서는 높은 품질로 작업하되, 앱용 모델에는 털 덩어리 형태, 텍스처, 필요한 곳의 털 카드 등 가벼운 표현을 사용한다. 어떤 조합이 적합한지는 사진 속 털 길이와 3D 미리보기 결과를 보고 정한다. 앱용 삼각형 수와 텍스처 크기는 실제 표시 크기와 Windows 성능 측정 뒤 확정한다.

고밀도 조각은 디테일 원본으로 보관한다. 애니메이션용 표면을 다시 구성하는 리토폴로지와 디테일 베이킹을 별도로 진행한다. 단순히 면 수를 줄이는 것만으로 걷기·앉기 변형에 적합해졌다고 판단하지 않는다. 관절 변형의 사전 검사는 최종 털 배치 전에 진행한다.

텍스처는 조명을 그림에 과하게 구워 넣지 않도록 만들고, 털 가장자리와 눈 주변을 여러 배경색에서 확인한다. 원본 `.blend` 파일과 앱용 메시·텍스처를 별도로 보관한다.

## 4. 리깅과 애니메이션

강아지용 사족 뼈대를 만들고 어깨, 앞다리, 뒷다리, 목, 꼬리의 변형을 확인한다. Unity에는 사람형 `Humanoid` 대신 `Generic` 리그로 전달한다. 기본 클립은 `Idle`, `Walk`, `Sit`, `Lie`, `Sleep`, `TailWag`이다. 걷기는 제자리 재생으로 만들고, 화면 이동은 앱 코드에서 처리한다.

짧은 클립을 각각 정면과 측면에서 검토한다. 걷기에서는 발이 바닥을 지나가거나 심하게 미끄러지지 않는지, 앉기와 눕기에서는 몸통과 털이 관절을 자연스럽게 따라가는지 확인한다.

## 5. 검토와 전달물

각 체크포인트마다 **정면·측면·45도 렌더**를 실제 사진과 나란히 비교한다. 보호자가 지적한 얼굴과 체형 차이를 먼저 고친 뒤 다음 단계로 간다. 닮은 정도는 자동 생성 점수만으로 판단하지 않는다.

| 순서 | 검토 결과물 | 다음 단계로 넘어가는 기준 |
| --- | --- | --- |
| 기반 검사 | 메시 구성과 수정 필요점, 세 각도 미리보기 | 서 있는 체형과 필요한 관절을 만들 수 있는 기반 선택 |
| 외형 수정 | 무채색 표면·털 부피 가이드와 사진 비교 | 짧은 주둥이, 눈·귀 위치, 몸통·다리·꼬리 비율 확인 |
| 털·재질 | 중립 조명에서의 근접 렌더와 전신 렌더 | 눈과 코가 털에 가려지지 않고, 얼굴·가슴·꼬리의 털 방향과 부피가 사진에 가까움 |
| 변형 | 걷기·앉기·눕기 미리보기 | 관절 붕괴, 몸·털 관통, 발 미끄러짐 수정 |
| 앱용 자산 | Windows에서 실제 크기로 표시 | 닮은 특징 유지, 투명 가장자리와 성능 확인 |

최종 자산은 Blender 원본 `.blend`, 앱용 메시 `FBX`, 필요한 텍스처, 애니메이션 클립, 비교 렌더를 준비한다. Unity에서 최종 재질·투명도·성능을 다시 확인한다.

사진 기반 3D 생성 도구는 초기 형태 후보를 빠르게 만드는 선택지다. 실제 강아지의 닮은 정도와 애니메이션 품질을 목표로 할 때는 생성 결과를 그대로 최종본으로 쓰지 않고 Blender에서 수정한다. 외부 생성 서비스의 유료 작업은 입력 자료와 예상 비용을 정한 후 진행한다.
