# 로컬 작업 인수인계

최종 정리: **2026-10-06**. 클라우드에서 진행한 모델링과 대화의 결정 사항을 Windows 로컬 Codex에서 이어가기 위한 시작 문서다. 대화 전문과 첨부 사진을 복사한 문서는 아니며, 작업에 필요한 요구사항·변경 기록·파일 위치·남은 문제를 정리했다.

`fullbody05`는 가장 최근 전달한 편집 가능한 작업본이다. 실제 강아지와 최대한 닮게 만들기 위한 추가 개선이 필요하며, 최종 외형 승인은 받지 않았다.

이전 열린 입 전신 모델은 [fullbody04 Drive ZIP](https://drive.google.com/file/d/12AAa1uMhGlbhQdnXcjg78dahfr6Lh8Cb/view)과 [기존 렌더](../Previews/fullbody04)로 보관한다. 로컬 재개의 기본 파일은 `fullbody05`다.

## 사용자가 정한 요구사항

- 우리 집 흰 포메라니안 오공이의 사진을 이용해 얼굴과 체형을 사실적으로 재현한다. 단순한 도형 조합이나 일반적인 포메 캐릭터로 만족시키는 프로젝트가 아니다.
- 사용자가 제공한 다각도 그림의 몸통, 다리 길이, 목 길이, 머리와 눈·코·주둥이 비율에 최대한 가깝게 진행한다.
- 가장 나중에 제공한 **입을 다문 정면·후면·위·좌우 측면 그림**이 기본 표정 기준이다. 실제 사진은 오공이의 개별 얼굴 특징과 털의 보조 기준이다.
- 걷기·앉기·잠자기·클릭 반응을 원한다. 앱은 Windows 바탕화면에서만 활동하고 다른 앱 창이 강아지를 가리는 방식으로 만든다.
- 우선 큰 구조와 계획을 잡고 단계적으로 만든다. 현재 우선순위는 모델의 닮은 정도와 디테일이다.
- 추가 구매가 필요한 모델 다운로드를 제작의 필수 조건으로 삼지 않는다. 참고로 본 유료 모델은 구매하거나 원본을 확보한 상태가 아니다.
- 대화의 파일 다운로드 링크가 반복해서 열리지 않아 모델 전달은 Google Drive를 사용했다. 이번에는 저장소 문서를 읽어 로컬에서 이어간다.

드래그, `Lie`, 일시 정지·설정 저장 등은 [앱 계획](PROJECT_PLAN.md)에 있는 설계 기준안이다. 달리기·장난감·밥 주기·친밀도는 이후 확장 후보이며 아직 구현하지 않았다.

## 지금까지 만든 것

- 모델 생성·털·재질·렌더·구조 검사·전달 스크립트: [ArtSource](../ArtSource/README.md).
- 얼굴 중심의 실험을 거쳐 전신 `fullbody04`를 만들고, 마지막 기본 표정 변경을 `fullbody05`에 반영했다.
- 연속 머리·목·몸통·네 다리 표면, 눈·각막·눈꺼풀, 코·콧구멍, 닫힌 주둥이·턱·입선, 작은 귀, 말린 꼬리를 구성했다.
- 부위별 Blender Hair Curves를 만들었다. 현재 총 털 곡선 수는 **431,664**이며 몸체 표면은 **298,822 정점 / 597,640 삼각형 면**이다. 이는 실시간 앱에 맞춘 자산 규모가 아니다.
- 정면·양 측면·후면·위·사선·얼굴 확대의 실제 Cycles 렌더 7장을 저장했다.
- 검사 대상 몸체·코·귀·꼬리에 경계 및 비다양체 모서리가 없음을 확인했다. 닫힌 기본형에 혀·치아 오브젝트와 입안 재질 면이 없음을 확인했다.
- 원본 참고 사진이 들어 있던 제작 장면과 별개로 **참고 사진을 제거한 전달용 `.blend`**를 저장하고 재개방했다. ZIP 무결성도 확인했다.

구조 검사는 사진과의 유사도 점수가 아니다. 기준 그림을 대화에서 육안으로 참고했지만, 원본 다각도 그림 파일을 작업 폴더에 확보해 픽셀 겹치기·실루엣 오차를 측정한 상태는 아니다. 털 아래 관절과 실제 길이는 추정이며 모델 내부 단위를 실측 미터로 해석하면 안 된다.

## 다음 로컬 작업 순서

1. [로컬 시작 안내](LOCAL_SETUP.md)에 따라 저장소와 모델을 준비한다. Windows Blender MCP로 현재 파일명과 장면의 오브젝트 수를 **실제로 읽어** 연결을 검증한다.
2. 열린 모델이 `fullbody05`인지 확인하고, 직접 편집할 사본을 별도 이름으로 저장한다. `fullbody04`와 원본 전달본은 보존한다.
3. 사용자의 개인 폴더에서 기존 사진과 최신 닫힌 입 다각도 그림을 찾는다. 클라우드의 `ReferencePhotos/`나 대화에 표시된 이미지가 저장소에 복사됐다고 가정하지 않는다.
4. 정면·측면의 투영과 바닥 기준을 맞추고 큰 실루엣부터 비교한다. 머리 크기, 눈 간격·높이, 코와 짧은 주둥이, 아래턱, 목·가슴 볼륨, 몸통과 다리 길이, 발 간격, 꼬리 높이를 우선 조정한다.
5. 큰 형태가 맞아가면 눈꺼풀·코·입선과 부위별 털 방향·길이·밀도를 다듬는다. 털을 숨겨 형태를 보고, 다시 켜서 최종 실루엣을 검토한다.
6. 실제 3D 렌더로 정면·양 측면·후면·위·사선·얼굴을 검토한다. 외형이 충분히 정리된 뒤 변형용 메시, 사족 리깅, 행동 클립, 앱용 털과 Unity 통합으로 넘어간다.

현재 클라우드 모델을 더 만들거나 기존 생성 파이프라인을 다시 실행하는 것이 재개의 첫 단계는 아니다. 이미 열린 로컬 모델과 실제 MCP 연결부터 확인한다.
