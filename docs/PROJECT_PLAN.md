# Desktop Pet 프로젝트 계획

## 1. 목표와 첫 출시 범위

우리 집 강아지를 닮은 3D 캐릭터가 Windows 바탕화면 아래쪽을 돌아다니다가 가끔 앉거나 잠들고, 마우스에 반응하는 프로그램을 만든다. 다른 프로그램 창을 열면 그 창이 강아지를 가린다. 캐릭터의 외형과 자연스러운 움직임을 중요한 품질 기준으로 삼는다.

첫 버전에는 다음을 포함한다.

- Windows 10/11의 바탕화면 계층에 3D 강아지 표시
- 작업 영역 아래쪽에서 좌우 걷기와 화면 끝 방향 전환
- `Idle`, `Walk`, `Sit`, `Lie`, `Sleep` 상태 전환
- 클릭 시 꼬리 흔들기 등 짧은 반응과 마우스 드래그
- 강아지 바깥 투명 영역의 클릭 통과
- 일시 정지, 종료, 기본 설정 저장

첫 버전은 한 대의 모니터를 기준으로 완성한다. 여러 모니터와 서로 다른 DPI 배율의 완전한 지원, 달리기, 소리, 장난감, 밥 주기와 친밀도는 다음 버전에서 다룬다.

## 2. 기술 기준안

| 역할 | 선택 | 이유와 검증 사항 |
| --- | --- | --- |
| 3D 모델·리깅·애니메이션 | Blender | 체형, 털 실루엣, 사족 보행을 직접 다듬을 수 있다. |
| 렌더링·행동 | Unity LTS + C# | 실시간 3D와 애니메이션 상태 제어에 적합하다. |
| 데스크톱 통합 | Windows 창 처리용 C# 계층 또는 플러그인 | 바탕화면 계층, 투명도, 클릭 통과, 창 위치와 DPI를 담당한다. |
| 모델 교환 | FBX + Unity `Generic` 리그 | 네 발 동물은 사람형 `Humanoid` 리그에 맞지 않는다. |

**Windows 통합 전 기술 검증:** Unity의 기본 창 설정만으로는 Windows 바탕화면 계층에 표시하기, 픽셀 단위 투명도, 투명 영역 클릭 통과가 보장되지 않는다. 임시 3D 도형으로 실제 Windows 10/11에서 이 조건을 확인한다. Windows Explorer의 바탕화면 창 계층을 이용하는 방식과 일반 창을 바탕화면 수준에 유지하는 방식을 비교한다. Explorer 재시작, 창 최소화와 바탕화면 표시, 아이콘 클릭, 앱 창의 앞뒤 순서까지 시험한다. 조건을 충족하지 못하면 창 표시 방식을 바꾸거나 렌더링과 창 표시를 분리한다. 이 검증을 마친 뒤 앱 구현 방식을 확정한다.

첫 버전은 **바탕화면에서만 보이는 펫**을 기준으로 한다. 강아지는 다른 앱 창 위에 떠 있지 않으며, 바탕화면에서는 클릭과 드래그가 가능해야 한다. 바탕화면 아이콘과 강아지가 겹칠 때 어느 쪽을 앞에 둘지는 3단계 창 실험 결과와 사용성을 보고 결정한다.

## 3. 구성 요소

```text
강아지 사진·짧은 움직임 영상
          ↓
Blender: 모델 → 털 표현 → 뼈대 → 애니메이션
          ↓ FBX
Unity: 캐릭터 프리팹 + Animator
          ↓
행동 상태 머신 ↔ 이동 제어 ↔ 마우스 상호작용
          ↓
Windows 창 계층: 투명도·클릭 통과·위치·작업 영역
          ↓
Windows 실행 파일
```

- `PetBrain`: 시간과 확률에 따라 다음 행동을 고른다. Windows API는 직접 다루지 않는다.
- `PetMotion`: 이동 방향, 속도, 경계 반사, 드래그 위치를 계산한다.
- `PetAnimator`: 행동을 애니메이션 클립과 꼬리·표정 반응에 연결한다.
- `PetInteraction`: 클릭, 포인터 접근, 드래그를 행동 이벤트로 바꾼다.
- `DesktopWindow`: 바탕화면 계층, 투명도, 클릭 통과, 표시 순서, 작업 영역과 DPI를 담당한다. Explorer가 재시작되면 연결을 복구한다.
- `PetSettings`: 사용자 설정을 저장한다.

실제 강아지 모델이나 창 표시 구현을 교체해도 행동 규칙을 유지할 수 있도록 경계를 나눈다.

## 4. 행동 규칙 초안

```text
              ┌── Sit ──┐
Idle ── Walk ─┤         ├── Idle
  │           └── Lie → Sleep ──┘
  └──────────────────────────────┘
```

- `Walk` 애니메이션은 제자리에서 재생하고 화면상의 위치는 코드가 옮긴다. 두 이동이 중복되지 않게 한다.
- 시간이 지나면 `Idle`, `Walk`, `Sit`, `Lie` 중 다음 행동을 고른다. `Sleep`은 누운 상태에서 시작한다.
- 클릭 반응은 현재 행동을 잠시 중단하고 재생한 뒤 이전 흐름으로 돌아간다.
- 드래그 중에는 자동 이동을 멈추고, 놓으면 유효한 위치에서 `Idle`로 돌아간다.
- 포인터 쳐다보기, `Run`, 장난감 행동은 기본 동작이 안정된 뒤 추가한다.

초기 행동 시간과 확률은 설정으로 조정할 수 있게 한다. 실제 값은 모델 크기와 클립 길이를 보고 정한다.

## 5. 캐릭터 제작 기준

필요한 자료는 자연광에서 찍은 얼굴 정면, 양쪽 측면, 뒤쪽, 전신 사진이다. 귀·눈·코가 잘 보이는 근접 사진과 걷기·앉기 영상이 있으면 더 좋다. 한 장만 있어도 시작할 수 있지만 보이지 않는 면은 추정해야 한다.

표현 방향은 **오공이를 사실적으로 닮게 만드는 것**으로 정했다. 얼굴 구조·전체 실루엣을 먼저 맞추고, 부위별 털과 재질을 정교하게 만든다. 애니메이션용 관절 변형을 확인하면서 앱용 털 표현을 따로 준비한다. 털 한 올마다 복잡한 실시간 시뮬레이션을 적용하는 방식은 피한다. 기존 v01·v02는 품질 미달로 채택하지 않았다. Meshy는 다운로드 결제가 필요해 현재 경로에서 제외하고, 사용자가 제공한 리트리버 모델 등 추가 결제 없이 접근할 수 있는 원본의 검사부터 기반을 다시 정한다.

Unity에 전달할 자산 규약:

- 강아지 전체를 교체 가능한 하나의 프리팹으로 제공한다.
- 네 발 동물용 뼈대를 Unity `Generic` 리그로 가져온다.
- 기본 클립 이름: `Idle`, `Walk`, `Sit`, `Lie`, `Sleep`, `TailWag`.
- 걷기는 제자리 재생을 기준으로 하며 정면 방향, 바닥 원점, 크기를 통일한다.
- 클릭 가능한 몸통 영역에 콜라이더를 둔다.

사진 기반 자동 3D 생성 도구는 초안 제작에 쓸 수 있다. 결과의 얼굴, 털 실루엣, 사족 리깅과 애니메이션은 검토하고 필요한 부분은 Blender에서 고친다. 닮은 정도를 우선하는 구체적인 작업 순서는 [3D 제작 계획](3D_ASSET_PLAN.md)을 따른다.

## 6. 개발 단계와 완료 기준

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| 0. 사진과 기준 정리 | 사진·영상 수집, 비율 분석, 표현 스타일 확정 | 정면·측면·후면과 얼굴 특징을 기록하고 모델링 기준 이미지를 정한다. |
| 1. 형태 제작 | Blender에서 얼굴·체형의 기본 형태와 털 실루엣 제작 | 여러 각도 렌더를 실제 사진과 비교해 닮은 정도를 확인한다. |
| 2. 세부 자산 제작 | 털·재질·텍스처, 사족 리깅과 행동 클립 | 관절 변형과 걷기·앉기·눕기·잠자기를 미리보기에서 확인한다. |
| 3. Windows 창 실험 | 임시 도형을 바탕화면에 표시하고 창 순서·입력 처리 확인 | 다른 앱 창이 도형을 가리고, 바탕화면에서는 도형을 클릭·드래그할 수 있으며, 투명 영역의 아이콘 클릭과 종료가 가능하다. Explorer 재시작 뒤에도 복구된다. |
| 4. 앱 통합 | 강아지 자산 가져오기, 행동 상태 머신, 클릭 반응, 드래그 | 작업 영역 안에서 자연스럽게 움직이고 마우스 입력이 안정적이다. |
| 5. 배포 준비 | 설정, 일시 정지·종료, 성능 조정, Windows 빌드 | 일반 작업 중에도 방해되지 않고 다시 실행해도 설정이 유지된다. |

각 단계가 끝날 때 화면 녹화나 스크린샷으로 결과를 확인한다. 현재 환경에는 Blender 4.3.2가 있으므로 0~2단계를 먼저 진행한다. Unity가 있는 Windows 환경에서 **3단계 창 실험을 통과한 뒤** 앱 통합 방식을 확정한다. 3D 원본은 앱의 창 표시 방식과 분리해 보관한다.

## 7. 저장소 구성안

```text

│   ├── PROJECT_PLAN.md
```

## 8. 구현 전에 확인할 사항

현재 기준안은 Blender에서 실제 강아지와 닮은 3D 자산을 먼저 만들고, 이후 Unity LTS를 사용할 수 있는 Windows 환경에서 바탕화면 전용 앱을 통합하는 것이다. 구현 전에 실제 Windows 버전과 화면 배율, 모니터 수, 바탕화면 아이콘과 강아지가 겹칠 때의 우선순위, 사진·영상 자료, Unity를 실행할 Windows 개발 환경을 확인한다.
